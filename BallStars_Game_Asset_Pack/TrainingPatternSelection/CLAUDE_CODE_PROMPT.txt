Before coding inspect and reuse the existing TrainingViewModel, pattern/training model, navigation, theme, typography, resource loading and scaling helpers. Do not create duplicate domain models.

SCREEN STRUCTURE
Use a portrait Column:
1. existing safe-area/top navigation with Back
2. compact `01_Header_Choose_Pattern.png`
3. native heading: “Select Training Pattern”
4. native difficulty filter chips: All / Beginner / Intermediate / Advanced
5. LazyColumn of pattern cards

Do not try to fit all patterns on one viewport; the list must scroll smoothly.

FILTERS
Prefer native Compose FilterChip-style controls styled to BallStars rather than PNG buttons. Filter the displayed list only. Difficulty categories should come from the existing model/config where possible.

PATTERN CARD
Create/reuse one component such as:
@Composable
fun TrainingPatternCard(
    pattern: TrainingPatternUiModel,
    onClick: () -> Unit,
    modifier: Modifier = Modifier
)

Each full-width card contains:
LEFT: square pattern thumbnail.
MIDDLE: native pattern name, short description, configurable difficulty stars, configurable duration, and configurable score/points if appropriate.
RIGHT: dynamically drawn 3×3 pattern preview plus right chevron.
The WHOLE card is clickable.

Do not bake text, difficulty, time, score or sequence into the thumbnail.

DYNAMIC MINI GRID
Prefer Compose Canvas. Draw a square 3×3 grid with fixed spatial mapping 1..9, then read pattern.sequence and draw nodes + connecting path in sequence order. Use BallStars cyan/gold treatment. This must automatically support new sequences without new PNGs.

DIFFICULTY
Difficulty is configurable. Build/reuse a native DifficultyStars(rating, maxRating=5) component. Read the value from current state/model. Never infer it from thumbnail colour or the mock-up.

SCORING
Scores/points are configurable too. Display the value from the model/config if this selection-screen UX exposes scoring. Do not hardcode point values.

CARD ACCENTS
Cyan/green/gold/purple can provide visual variety, but do NOT make accent colour secretly define difficulty unless that is already an explicit app rule.

NAVIGATION
On card tap call onPatternSelected(pattern.id) and navigate to that pattern’s explainer. The explainer then shows the selected pattern’s name, sequence, instructions, configurable difficulty/scoring and start action. Do not rebuild the explainer in this task.

RESPONSIVE DIMENSIONS
Reuse the same dimension logic as Setup, Grid Creator and Play Choice. No screenshot pixel coordinates.
Use fillMaxWidth, LazyColumn, dp spacing, safe drawing insets and existing scale helpers.
On shorter phones: reduce header height and decorative spacing first; keep cards comfortably tappable; let chips scroll horizontally if needed. Touch targets >=48dp.
