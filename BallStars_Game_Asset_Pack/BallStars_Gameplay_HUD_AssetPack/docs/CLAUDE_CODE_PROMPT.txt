============================================================
GAME PHASES
============================================================

Use/reuse existing state architecture. UI conceptually needs:

TIME_SELECTION
COUNTDOWN
ACTIVE
PAUSED
COMPLETE

Do not duplicate an existing equivalent game-state model.

TIME_SELECTION:
- show camera/grid live
- bottom HUD becomes time selector
- options: `30 SEC` and `60 SEC` only
- selected option uses green treatment
- use `05_Play_Button_Matched.png` as the START visual
- START stores selected duration and enters countdown

COUNTDOWN:
- camera/grid remain visible
- no scoring
- centre overlay counts 10, 9, ... 1
- then `GO!`
- use a Compose-drawn circular cyan/green ring matching the play/pause/active-target visual family
- each integer is exactly one second

ACTIVE:
- countdown timer starts
- scoring enabled
- grid target sequence advances
- HUD values update

PAUSED:
- freeze timer and scoring
- use `05_Play_Button_Matched.png` for RESUME
- provide END GAME as a secondary native action

COMPLETE:
- use current game completion/result navigation

============================================================
HIT / MISS FEEDBACK
============================================================

HIT:
- fast green/gold ring/burst around target
- optional floating points value only if existing scoring event provides it
- 350–500ms
- advance to next target

MISS:
- brief restrained red/orange ring
- do not wash whole camera red
- existing miss rule resets streak
