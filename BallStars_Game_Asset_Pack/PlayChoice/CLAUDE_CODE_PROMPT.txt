CLAUDE CODE PROMPT — BALLSTARS PLAY CHOICE SCREEN

Implement ONE screen in the existing BallStars Kotlin Multiplatform / Compose Multiplatform app.

PURPOSE
Ask the player whether they want to:
1. go through the Setup Steps,
2. go straight to Training Sessions,
3. go straight to Matches.

This screen appears after the player has already selected their preferred boy/girl presentation earlier in onboarding. However, THIS choice screen deliberately shows BOTH a boy and a girl in the main hero image to communicate that BallStars is for both.

IMPORTANT
The supplied concept reference is too wide for a real modern handset.
DO NOT reproduce its three-column desktop/tablet-like layout.

Build for PHONE PORTRAIT.

Reference handset:
Pixel 9, approximately 20:9 portrait.

The layout must use the real device width and height and remain responsive.

SCREEN API
============================================================

Create something equivalent to:

    onSetupSteps: () -> Unit,
    onTraining: () -> Unit,
    onMatches: () -> Unit,
    modifier: Modifier = Modifier

Use the project's existing navigation/state architecture if it already defines equivalent callbacks/routes.

Do not introduce a second navigation system.

============================================================
PORTRAIT LAYOUT
============================================================

Use a portrait-first layout.

Suggested structure:

Column(
    Modifier
        .fillMaxSize()
        .background(BallStarsColors.bgDeep)
        .windowInsetsPadding(WindowInsets.safeDrawing)
) {
    Hero
    Heading
    SupportingText
    ChoiceList
}

Unlike the explainer screens, this is a CHOICE screen.

Recommended vertical proportions on a normal Pixel 9 sized handset:

Hero:
~32–36% of usable height

Heading + intro:
~12–15%

Three choices:
remaining ~50–55%

DO NOT force a 50/50 explainer layout onto this screen.

============================================================
CHOICE LAYOUT — CRITICAL
============================================================

DO NOT put the three options side-by-side.

On a phone portrait screen, stack them VERTICALLY.

Use three large horizontal choice cards:

[ icon/image ] [ Setup Steps          > ]
               [ Set up your grid...    ]

[ icon/image ] [ Training Sessions    > ]
               [ Practise skills...     ]

[ icon/image ] [ Matches              > ]
               [ Challenge friends...  ]

Each card should fill the available width.

Suggested:
- horizontal margin: 20–24dp
- card height: approximately 92–112dp
- gap: 12–16dp
- corner radius: 20–24dp
- minimum interactive height: 64dp

On very tall screens the cards may be slightly larger.

REUSABLE CHOICE COMPONENT
============================================================

Create a small reusable component, e.g.:

@Composable
private fun PlayChoiceCard(
    title: String,
    description: String,
    image: Painter,
    accentColor: Color,
    onClick: () -> Unit,
    modifier: Modifier = Modifier
)

Suggested structure:

Surface(
    onClick = onClick,
    shape = RoundedCornerShape(22.dp),
    color = BallStarsColors.surface,
    border = BorderStroke(1.dp, accentColor.copy(alpha = 0.8f))
) {
    Row(
        verticalAlignment = Alignment.CenterVertically
    ) {
        Image(...)
        Column(Modifier.weight(1f)) {
            Text(title)
            Text(description)
        }
        Chevron
    }
}

Use existing BallStars components if equivalent components already exist.

============================================================
RESPONSIVE DIMENSION LOGIC
============================================================

Do NOT hardcode screen pixel coordinates.

Use BoxWithConstraints only if necessary.

Prefer:
- fillMaxWidth()
- weight()
- aspectRatio()
- dp spacing tokens
- safe drawing insets

Normal/tall phone:
Hero ~34%
Intro ~13%
Choices ~53%

Short phone:
1. reduce hero height slightly
2. reduce vertical gaps
3. reduce card heights modestly
4. allow content area to scroll if required

Never solve space pressure by:
- putting choices side-by-side
- clipping text
- cropping children's faces
- hiding a choice
- shrinking touch targets below 48dp
